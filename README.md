# In-memory cache с TTL

Простой потокобезопасный in-memory кэш на Go с поддержкой времени жизни записей (TTL).

Кэш хранит пары ключ-значение в памяти, скрывает истекшие записи при чтении и умеет очищать их вручную или через фоновую горутину.

## Возможности

- Потокобезопасные операции через `sync.RWMutex`.
- Generic API для любых сравнимых ключей и любых значений.
- TTL для каждой записи.
- Получение, удаление и ручная очистка записей.
- Фоновая периодическая очистка истекших записей.
- Проверка существования ключа через `Exists`.
- Получение актуальных ключей через `Keys`.
- Ограничение максимального количества записей через `maxSize`.

## Быстрый пример

```go
package main

import (
	"fmt"
	"log"
	"time"

	ttlcache "github.com/maestrying/in-memory-cache"
)

func main() {
	cache, err := ttlcache.New[string, string](100)
	if err != nil {
		log.Fatal(err)
	}

	if err := cache.Set("user:1", "Maxim", time.Minute); err != nil {
		log.Fatal(err)
	}

	value, ok := cache.Get("user:1")
	if !ok {
		fmt.Println("key does not exist or has expired")
		return
	}

	fmt.Println(value)
}
```

## API

### Создание кэша

```go
cache, err := ttlcache.New[string, string](100)
```

`New` создает кэш с ограничением по количеству записей. Если `maxSize <= 0`, возвращается `ErrInvalidMaxSize`.

```go
cache, err := ttlcache.NewWithAutoCleanup[string, string](100, time.Second)
if err != nil {
	log.Fatal(err)
}
defer cache.Close()
```

`NewWithAutoCleanup` дополнительно запускает фоновую горутину, которая вызывает `Cleanup` с заданным интервалом. После использования такого кэша нужно вызвать `Close`, чтобы остановить горутину.

Если `cleanupInterval <= 0`, возвращается `ErrInvalidInterval`.

### Set

```go
err := cache.Set("user:1", "Maxim", time.Minute)
```

Добавляет или обновляет значение по ключу и задает TTL. При обновлении существующего ключа значение и TTL перезаписываются.

Если кэш заполнен, `Set` сначала удаляет истекшие записи. Если после этого свободного места нет, возвращается `ErrCacheFull`.

### Get

```go
value, ok := cache.Get("user:1")
```

Возвращает значение и `true`, если ключ существует и запись не истекла. Если ключ отсутствует или TTL уже истек, возвращается нулевое значение типа и `false`.

### Delete

```go
cache.Delete("user:1")
```

Удаляет ключ из кэша. Если ключа нет, операция ничего не делает.

### Cleanup

```go
cache.Cleanup()
```

Удаляет все истекшие записи из кэша.

### Exists

```go
ok := cache.Exists("user:1")
```

Возвращает `true`, если ключ есть в кэше и запись не истекла.

### Keys

```go
keys := cache.Keys()
```

Возвращает срез ключей, записи которых еще не истекли. Порядок ключей не гарантируется, так как внутри используется `map`.

## TTL

TTL задается отдельно для каждой записи:

```go
cache.Set("session:1", "token", 10*time.Minute)
```

Запись считается истекшей, когда текущее время достигло `expiresAt` или стало больше него. Нулевой или отрицательный TTL делает запись сразу истекшей.

Истекшие записи:

- не возвращаются из `Get`;
- не считаются существующими в `Exists`;
- не попадают в `Keys`;
- физически удаляются при `Cleanup`, фоновой очистке или при попытке добавить новую запись в заполненный кэш.

## Ограничение размера

Кэш создается с максимальным количеством записей:

```go
cache, err := ttlcache.New[string, string](2)
```

Если лимит достигнут и в кэше нет истекших записей, новая запись не добавляется:

```go
if errors.Is(err, ttlcache.ErrCacheFull) {
	fmt.Println("cache is full")
}
```

## Ошибки

Пакет экспортирует следующие ошибки:

```go
ttlcache.ErrInvalidMaxSize
ttlcache.ErrInvalidInterval
ttlcache.ErrCacheFull
```

Их удобно проверять через `errors.Is`.

## Особенности реализации

- Кэш полностью хранится в памяти процесса.
- Данные не сохраняются между перезапусками приложения.
- Операции безопасны для одновременного использования из нескольких горутин.
- Для фоновой очистки используется `time.Ticker`; его работа останавливается через `Close`.
